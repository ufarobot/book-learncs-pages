    Кодирование информации

    Кодирование — это представление информации по выбранному правилу.

    Когда вы вводите букву A, компьютер не хранит картинку с буквой. Он хранит число \(65\), а число записывает битами:

    \[ \text{A} \rightarrow 65 \rightarrow \mathtt{01000001}_2 \]

    Так же устроены текст, изображения, звук и файлы: объект переводят в числа, числа — в биты, а при чтении выполняют обратные шаги.

    Кодом называют и само правило, и получившуюся запись.

    Обратное действие называют декодированием: по коду восстанавливают исходную информацию.

    Без правила кодирования набор знаков не имеет однозначного смысла. Одна и та же последовательность может обозначать число, символ, цвет пикселя или часть звука.

    Например, байт \(\mathtt{01000001}_2\) можно прочитать по-разному:

    Азбука Морзе

    Такой код можно использовать там, где проще передать два типа сигналов: короткий и длинный. Например, сообщение можно передать звуком, светом или радиосигналом.

    Азбука Морзе — простой пример кода без компьютера. Буквы и цифры в ней заменяются короткими и длинными сигналами: точками и тире.

    Точка означает короткий сигнал, тире — длинный. Паузы тоже часть правила: короткая пауза отделяет сигналы внутри одной буквы, более длинная — соседние буквы, еще более длинная — слова. Без пауз сообщение слилось бы в одну цепочку.

    Слово SOS удобно для первого разбора: в нем только два разных символа. Буква S кодируется тремя короткими сигналами, а буква O — тремя длинными.

    Символ Код Морзе
    S ...
    O ---
    S ...

    Получаем сообщение:

    \[ \text{SOS} \rightarrow \class{morse}{\text{... --- ...}} \]

    При декодировании используют ту же таблицу в обратную сторону:

    \[ \class{morse}{\text{... --- ...}} \rightarrow \text{SOS} \]
    Задачи для тренировки: кодирование и декодирование

    1. По таблице Морзе закодируйте слово CAT.

    Ответ

    CAT → -.-. .- -

    2. Декодируйте сообщение .--- .- ...- .-.

    Ответ

    .--- .- ...- .- → JAVA

    3. Почему для декодирования сообщения ... --- ... нужна таблица Морзе?

    Ответ

    Потому что точки и тире сами не называют буквы. Таблица задает правило: какая группа сигналов какой букве соответствует.

    Двоичный код, бит и байт

    Двоичный код — это код, состоящий из двух знаков: \(0\) и \(1\).

    Цифровому устройству проще надежно различать два состояния: сигнал есть или сигнала нет, напряжение выше порога или ниже порога, участок памяти намагничен одним способом или другим. Поэтому данные хранят как последовательности нулей и единиц.

    Небольшая помеха обычно не меняет смысл данных: если сигнал все равно попал в зону \(0\) или в зону \(1\), схема прочитает его правильно.

    Бит — одна двоичная ячейка данных. Он хранит одно из двух значений: \(0\) или \(1\). Группа из \(8\) бит называется байтом.

    Если под значение выделено \(I\) бит, число разных кодов равно

    \[ N = 2^I \]

    Каждый новый бит удваивает число возможных кодов.

    Биты Число кодов
    \(1\) \(2\)
    \(2\) \(4\)
    \(3\) \(8\)
    \(4\) \(16\)
    \(8\) \(256\)

    Для одного байта:

    \[ 2^8 = 256 \]

    Значит, один байт может хранить один из \(256\) разных кодов.

    Кодирование чисел

    Чтобы записать число в памяти, сначала выбирают, сколько бит под него выделить. Если число беззнаковое, первый код соответствует \(0\), следующий — \(1\), и так далее.

    Например, в \(4\) битах можно записать \(16\) разных кодов:

    В \(8\) битах можно закодировать \(2^8 = 256\) беззнаковых значений: от \(0\) до \(255\). Число \(65\) в одном байте записывается так:

    \[ 65 \rightarrow \mathtt{01000001}_2 \]

    Количество кодов и максимальное значение отличаются на единицу, потому что счет начинается с \(0\):

    \[ 0,\ 1,\ 2,\ \dots,\ 255 \]

    Кодирование символов

    Текст хранится через числовые коды символов. При сохранении программа находит код каждого символа и записывает этот код битами. При чтении она получает число и по таблице восстанавливает символ.

    Например, латинской букве B в ASCII соответствует число \(66\), поэтому в байте она записывается как \(\mathtt{01000010}_2\).

    ASCII — один из первых широко используемых стандартов кодирования символов. Он задает коды от \(0\) до \(127\), то есть \(128\) кодов. Эти коды помещаются в \(7\) бит, а в байте занимают младшую половину диапазона.

    Фрагмент ASCII-таблицы

    Кириллицы в базовом ASCII нет. В старых однобайтовых кодировках старшую половину байта, коды \(128\)–\(255\), использовали для национальных алфавитов. В современных системах обычно применяют Unicode и UTF-8: они позволяют кодировать символы разных языков в едином наборе правил.

    Как данные превращаются в числа

    Символ удобно заменить числом из таблицы. Со звуком, изображением, температурой или яркостью сложнее: такие данные могут меняться непрерывно, а компьютер хранит конечные коды.

    Переход от непрерывных данных к отдельным значениям называют дискретизацией. Например, звук измеряют в отдельные моменты времени, а изображение разбивают на отдельные пиксели.

    Цифровое представление строится так:

    1. исходные данные разбивают на отдельные элементы;
    2. каждому элементу ставят в соответствие число;
    3. число записывают в двоичном виде;
    4. при чтении выполняют обратные шаги.

    Примеры дискретизации:

    Непрерывность и дискретность относятся к представлению. Температура тела меняется непрерывно, а запись \(36{,}6\) уже дискретна: значение округлено и записано конечным числом цифр.

    Кодирование изображений

    Изображение представляют как прямоугольную сетку пикселей. Цвет каждого пикселя кодируется отдельно, поэтому объем изображения без сжатия зависит от разрешения и глубины цвета.

    Если каждый пиксель хранит \(24\) бита цвета, по \(8\) бит обычно выделяют на красный, зеленый и синий каналы.

    Цвет часто записывают в HEX-формате. После знака # идут три пары шестнадцатеричных цифр: для красного, зеленого и синего каналов. Например, #FF0000 означает красный цвет: \(R = 255\), \(G = 0\), \(B = 0\).

    Цвет Название R G B Байты HEX
    черный 0 0 0 00000000 00000000 00000000 #000000
    белый 255 255 255 11111111 11111111 11111111 #FFFFFF
    красный 255 0 0 11111111 00000000 00000000 #FF0000
    зеленый 0 255 0 00000000 11111111 00000000 #00FF00
    синий 0 0 255 00000000 00000000 11111111 #0000FF

    Кодирование звука

    При цифровой записи звук представляют как последовательность измерений. Микрофон превращает колебания воздуха в электрический сигнал, а устройство записи через равные промежутки времени снимает его значение.

    Одно измеренное значение сигнала называют отсчетом. Частота дискретизации показывает, сколько отсчетов записывают за одну секунду. Например, частота \(44{,}1\) кГц означает \(44\,100\) отсчетов в секунду.

    Каждый отсчет округляют до одного из доступных уровней и записывают битами. Если на один отсчет выделено \(24\) бита, можно различить \(2^{24}\) уровней амплитуды.

    Для одного канала без сжатия объем записи длительностью \(t\) секунд считают так:

    \[ \text{объем в битах} = \text{частота дискретизации} \cdot t \cdot \text{бит на отсчет} \]

    Для стереозвука хранят два канала, левый и правый, поэтому объем умножается на \(2\).

    Задачи для тренировки: дискретизация

    1. В изображении \(100 \times 100\) пикселей. На каждый пиксель выделено \(24\) бита. Найдите объем изображения без сжатия в битах.

    Ответ

    \[ 100 \cdot 100 \cdot 24 = 240000\text{ бит} \]

    2. Монофонический звук записан с частотой \(8000\) отсчетов в секунду. На один отсчет выделено \(8\) бит. Найдите объем \(10\) секунд записи без сжатия.

    Ответ

    \[ 8000 \cdot 10 \cdot 8 = 640000\text{ бит} \]
    \[ 640000 : 8 = 80000\text{ байт} \]

    3. Почему увеличение глубины цвета обычно увеличивает объем изображения?

    Ответ

    Потому что на каждый пиксель выделяется больше бит. Количество пикселей остается тем же, но объем одного пикселя растет.

    Как программа читает файл

    До этого мы рассматривали данные как элементы со смыслом: символы, пиксели, отсчеты звука. На диске смысловых элементов уже нет — там лежит последовательность байтов.

    Чтобы байты снова стали изображением, звуком или текстом, программе нужно знать формат файла. Формат задает, как читать байты: где искать размеры изображения, глубину цвета, частоту звука, число каналов, имя автора и другие параметры.

    Расширение файла помогает понять, какой формат ожидается. Например, в имени photo.png расширение .png подсказывает, что файл должен быть изображением PNG.

    Расширение не меняет данные само по себе. Если переименовать image.png в image.jpg, байты внутри файла не станут JPEG-изображением. Для настоящего изменения формата нужна программа, которая прочитает старый формат и запишет данные по правилам нового формата.

    Формат отвечает за то, как прочитать байты. Размер файла отвечает на другой вопрос: сколько места занимает эта последовательность байтов. Для расчета нужны биты, байты и более крупные единицы.

    Как считать объем данных

    Размеры файлов обычно записывают в байтах. Формулы кодирования часто дают результат в битах: например, «количество пикселей умножить на бит на пиксель». Поэтому в задачах приходится следить за единицами измерения: когда результат в битах, когда в байтах, когда нужно делить или умножать на \(8\).

    Основные единицы объема данных:

    В задачах этой главы используются двоичные кратные единицы:

    \[ 1\text{ КБ} = 1024\text{ байта} = 2^{10}\text{ байт} \]
    \[ 1\text{ МБ} = 1024\text{ КБ} = 2^{20}\text{ байт} \]

    Для множителя \(1024\) в стандартах есть отдельные названия: кибибайт, мебибайт, гибибайт. В учебных задачах чаще пишут привычные обозначения КБ, МБ, ГБ. Здесь КБ означает \(1024\) байта.

    В характеристиках накопителей и сетевых скоростей иногда используют десятичный счет по \(1000\). Из-за этого числа в рекламных спецификациях и в учебных задачах могут отличаться.

    Если данные хранятся без сжатия

    Теперь можно вернуться к самим данным. Без сжатия каждый элемент хранится отдельно: символ текста, пиксель изображения или отсчет звука. Поэтому расчет идет в два шага: сначала находят количество элементов, затем умножают на число бит для одного элемента:

    \[ \text{объем в битах} = \text{количество элементов} \cdot \text{бит на один элемент} \]

    Для текста элементом может быть символ, для изображения — пиксель, для звука — отсчет.

    Если сообщение кодируется кодом фиксированной длины, сначала находят, сколько бит требуется на один символ. Для алфавита из \(N\) символов выбирают минимальное число бит \(i\), для которого выполняется

    \[ N \le 2^i \]

    Тогда сообщение длины \(L\) символов занимает

    \[ I = L \cdot i \]

    бит.

    Задача:

    Робот понимает четыре команды: вверх, вниз, влево и вправо. Сообщение состоит из \(11\) команд. Найдите его объем.

    Решение:

    Для четырех команд нужно \(2\) бита на одну команду:

    \[ 4 = 2^2 \]

    Тогда полный объем сообщения:

    \[ 11 \cdot 2 = 22\text{ бита} \]

    Ответ: \(22\) бита.

    Задача:

    Цветное изображение имеет размер \(640 \times 480\) пикселей. На каждый пиксель выделено \(24\) бита. Найдите объем изображения без сжатия.

    Решение:

    Количество пикселей:

    \[ 640 \cdot 480 = 307200 \]

    Общий объем в битах:

    \[ 307200 \cdot 24 = 7372800\text{ бит} \]

    Переведем в байты:

    \[ 7372800 : 8 = 921600\text{ байт} \]

    Переведем в килобайты:

    \[ 921600 : 1024 = 900\text{ КБ} \]

    Ответ: \(900\) КБ.

    Такая оценка показывает объем основных данных. Реальный файл может быть больше из-за служебных данных формата или меньше из-за сжатия.

    Задачи для тренировки: измерение информации

    1. Сколько бит в \(5\) КБ?

    Ответ

    \[ 5 \cdot 1024 \cdot 8 = 40960\text{ бит} \]

    2. Переведите \(4096\) байт в килобайты.

    Ответ

    \[ 4096 : 1024 = 4\text{ КБ} \]

    3. Сообщение содержит \(3500\) символов. На каждый символ выделен \(1\) байт. Найдите объем сообщения в байтах и битах.

    Ответ

    \(3500\) байт.

    \[ 3500 \cdot 8 = 28000\text{ бит} \]

    4. Изображение \(320 \times 200\) пикселей хранится с глубиной \(8\) бит на пиксель. Найдите объем без сжатия.

    Ответ

    \[ 320 \cdot 200 \cdot 8 = 512000\text{ бит} \]
    \[ 512000 : 8 = 64000\text{ байт} = 62{,}5\text{ КБ} \]

    Когда числу не хватает бит

    До этого мы подбирали количество бит так, чтобы данных хватило. У вычислений есть обратная сторона: иногда число бит уже фиксировано, и результат может в него не поместиться.

    Фиксированное число бит для значения называют разрядной сеткой. Если в разрядной сетке \(I\) бит, можно записать \(2^I\) разных кодов. Для беззнаковых целых чисел диапазон начинается с \(0\) и заканчивается числом \(2^I - 1\).

    Например, в \(4\) битах можно записать

    \[ N = 2^4 = 16 \]

    разных беззнаковых значений: от \(0\) до \(15\).

    Следующее число, \(16\), уже требует пятого бита:

    \[ 15 + 1 = 16, \qquad \mathtt{1111}_2 + \mathtt{0001}_2 = \mathtt{10000}_2 \]

    Если хранить можно только \(4\) бита, старший пятый бит не помещается. В системах, где переполнение не проверяется отдельно, может остаться только младшая часть:

    \[ \mathtt{10000}_2 \rightarrow \mathtt{0000}_2 \]

    Если результат операции выходит за диапазон разрядной сетки, возникает переполнение.

    Переполнение — не единственная причина потери данных. Если непрерывное значение записывают конечным числом кодов, часть точности теряется. Поэтому вещественные числа обычно хранятся приближенно: значение вроде \(0{,}1\) не всегда представимо в памяти абсолютно точно.

    Задача:

    Сколько бит нужно, чтобы хранить беззнаковые целые числа от \(0\) до \(1000\)?

    Решение:

    Нужно не меньше \(1001\) разных значений: от \(0\) до \(1000\).

    Проверим степени двойки:

    \[ 2^9 = 512,\qquad 2^{10} = 1024 \]

    \(9\) бит не хватает, \(10\) бит хватает.

    Ответ: \(10\) бит.

    Задача:

    В беззнаковой \(8\)-битной разрядной сетке хранится число \(250\). Что произойдет при прибавлении \(10\), если оставить только младшие \(8\) бит?

    Решение:

    Точный результат:

    \[ 250 + 10 = 260 \]

    В \(8\) битах можно хранить значения от \(0\) до \(255\), поэтому \(260\) не помещается.

    Если оставить только остаток по \(256\), получится:

    \[ 260 - 256 = 4 \]

    Ответ: произойдет переполнение, останется значение \(4\).

    Какие значения помещаются в типы Java

    В Java размер основных числовых типов фиксирован, поэтому тип сразу задает разрядную сетку, диапазон и точность.

    Тип Размер Что хранит Диапазон или точность
    int \(4\) байта целые числа от \(-2^{31}\) до \(2^{31} - 1\)
    long \(8\) байт большие целые числа от \(-2^{63}\) до \(2^{63} - 1\)
    double \(8\) байт вещественные числа примерно \(15\)–\(17\) значащих десятичных цифр

    Если значение выходит за диапазон int или long, возникает переполнение. Если значение хранится в double, оно может быть записано приближенно: диапазон большой, но точность конечна.

    Задачи для тренировки: диапазоны и переполнение

    1. Сколько разных значений можно закодировать в \(6\) битах?

    Ответ

    \[ 2^6 = 64 \]

    2. Какой диапазон беззнаковых целых чисел можно хранить в \(6\) битах?

    Ответ

    От \(0\) до \(63\).

    3. Сколько бит нужно, чтобы хранить беззнаковые числа от \(0\) до \(255\)?

    Ответ

    Нужно \(256\) разных значений.

    \[ 2^8 = 256 \]

    Ответ: \(8\) бит.

    4. В \(4\)-битной беззнаковой разрядной сетке хранится число \(14\). Что останется после прибавления \(5\), если оставить только младшие \(4\) бита?

    Ответ

    Точный результат:

    \[ 14 + 5 = 19 \]

    В \(4\) битах есть \(16\) кодов, поэтому останется

    \[ 19 - 16 = 3 \]

    5. Какой тип Java выбрать для значения \(3000000000\): int или long?

    Ответ

    long.

    Число \(3000000000\) больше максимального значения int.
